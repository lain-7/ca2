# CA2 小组汇报：内容取舍与预期问题

前提：35 分钟纯讲解，Q&A 另算；评分看重**清晰度、现场演示、发现的洞察、问答、全员参与**。

---

## 一、时间预算（35 分钟）

| 段落 | 分钟 | 说明 |
|------|------|------|
| 开场 + 蜜罐/SSH 概念 | 4 | 点到为止，别讲成教科书 |
| 系统搭建（拓扑 + 证据截图） | 4 | 一张拓扑图 + 关键截图，不逐步念命令 |
| 现场演示（攻击→捕获→分析） | 10 | **重头戏**，评分里专门有“演示”项 |
| 日志分析发现 | 8 | 用户名/密码/命令/IP 溯源的结论 + 图表 |
| 加固与检测（压缩版） | 4 | 只给结论和那张分数曲线，细节留 Q&A |
| 安全建议 | 3 | 5 条，每条一句话配一个数据依据 |
| 收尾 + 局限 | 2 | 诚实说局限，反而加分 |

全员参与是评分项：确保每个人至少主讲一段。

## 二、哪些可以砍，怎么砍

**重点保留**（评分直接相关）：
- 现场演示：攻击机发起登录 → Cowrie 抓到 → 分析脚本出报告。这是“演示”评分项的核心，别省。
- 核心发现：Top 用户名/密码/命令、IP 地理分布、威胁结论。
- 5 条安全建议（必须和你们的数据对应）。

**压缩表达**（深但费时）：
- **检测器 + 六步加固（313→118 分）**：这是你们最亮的工作，但展开要 20 分钟。
  砍法：用**一句话 + 一张分数曲线图**带过——
  “我们还做了一个蜜罐识别器，并据此把 Cowrie 的暴露分降了 62%，完整的五层模型和逐步对照在报告第 X 章。”
  想深入的留给 Q&A，老师多半会追问，正好接住。
- **VM 搭建逐步命令**：砍成一张拓扑图 + “详见用户指南”。
- **OVA→KVM 迁移细节**：口头**完全省略**，它只属于环境说明文档。
- **工具代码/内部实现**：不要贴代码，只展示它**产出什么**（报告、图表）。

**省略的通用话术**：
- “由于时间关系，X 的完整细节在报告第 N 章，这里只讲结论。”
- “这部分展开可以单独讲很久，今天给结论，欢迎在 Q&A 深入。”
- 关键是**signpost**：告诉老师东西在哪（哪章/哪个文档），而不是假装没做。

## 三、如果我是老师，可能问的 20 个问题

> 用来自测。每条后面括号里是**考察点**（答题方向），不是答案。

**概念**
1. 蜜罐和防火墙 / IDS 有什么本质区别？（蜜罐是诱捕+情报，不是拦截）
2. 低交互、中交互、高交互蜜罐的区别？Cowrie 属于哪种，为什么？（交互深度 vs 风险）
3. Cowrie 为什么“接受任意密码也能登录”？这是缺陷还是设计？（诱捕设计，否则抓不到后续行为）
4. 密码认证和密钥认证，为什么后者更安全？（可爆破性、凭据可被猜）

**搭建**
5. 你们两台机器怎么联网的？为什么蜜罐要和真实网络隔离？（防跳板/横向移动）
6. Cowrie 默认在 2222 而不是 22，真实部署里有什么影响？你们在 VPS 上怎么处理的？（22 重定向到 2222）
7. `cowrie start` 之后，你怎么确认它真在工作？日志在哪？（status / tail json）

**攻击模拟**
8. 你们模拟了多少次登录？字典怎么选的？（≥20 次，弱口令来源）
9. 你们脚本模拟的攻击，和真实攻击者的行为有什么不同？（真实更随机、更自动化、来源更广）

**日志分析**
10. 最高频的用户名和密码是什么？说明了什么？（root/admin + 弱口令，自动化扫描特征）
11. 攻击者登录后最常执行哪些命令？分别想干什么？（侦察：whoami/uname/下载 payload）
12. IP 地理溯源怎么做的？数据来源是什么？有什么局限？（ip-api，免费/限速/可被代理绕过）
13. 内网 IP 的威胁等级你们怎么判定？这个判定可靠吗？（规则判定，坦诚说它只是启发式）
14. 成功登录率 X% 说明蜜罐防护强还是弱？这个指标本身有意义吗？（蜜罐本就该被登进，指标要重新解读）

**威胁与建议**
15. 攻击者从被攻陷的系统能“学到”什么？对真实组织的风险是什么？（信息泄露、立足点、横向移动）
16. 你们 5 条建议里哪条最重要？为什么？它和你们的哪个数据对应？（能把建议挂回数据）
17. 为什么“禁用 root 直接登录”有用，即使攻击者已经拿到密码？（提权门槛、审计）

**深度与局限**
18. 蜜罐能被识破吗？攻击者怎么判断这是个蜜罐？（引出你们的检测器：协议/文件系统/命令行为层）
19. 你们把 Cowrie 暴露分从 313 降到 118，为什么降不到 0？哪几层改不动？（协议层/认证层是架构性的）
20. 在 VPS 上跑蜜罐有什么额外风险？你们怎么防止它变成攻击跳板？（出站收紧、进程加固、服务商 abuse）

## 四、临场小建议

- 演示提前**录一段屏**做备份，现场网络/环境翻车时能顶上。
- 分数曲线、Top 统计、IP 分布各准备一张图，比念数字有效。
- 被问到不会的，诚实说“这部分我们没深入，但按……思路应该是”，比硬编强。
- 局限主动说（如 IP 可被代理伪装、内网模拟不等于真实流量），显得你们理解更透。
